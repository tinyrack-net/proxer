## 준비물

- HTTP/WebSocket 트래픽을 받을 수 있는 공개 서버
- 노출할 로컬 HTTP 서비스
- npm으로 설치하는 경우 Node.js 24 이상

---

## 설치

<Tabs>
  <TabItem label="Windows">

    [GitHub Releases](https://github.com/tinyrack-net/proxer/releases)에서 Windows용 독립 실행 파일을 내려받습니다.

    ```powershell
    proxer.exe --version
    ```

  </TabItem>
  <TabItem label="macOS / Linux">

    ```bash
    brew install tinyrack-net/tap/proxer
    ```

  </TabItem>
  <TabItem label="npm">

    npm은 모든 플랫폼에서 사용할 수 있는 범용 설치 방법입니다.

    ```bash
    npm install -g @tinyrack/proxer
    ```

  </TabItem>
  <TabItem label="Docker">

    ```bash
    docker run --rm tinyrack/proxer --version
    ```

  </TabItem>
</Tabs>

## 처음 시작하기

처음 Proxer를 사용한다면 다음 순서로 공개 서버 하나를 띄우고 로컬 서비스 하나를 노출합니다.

<Steps>

1. **공개 서버 시작**

   공개 트래픽을 받을 서버에서 Proxer를 실행합니다.

   ```bash
   proxer server --listen 0.0.0.0:8080 --domain your-server.example.com --token dev-token
   ```

   이 서버는 같은 포트에서 공개 요청과 터널 제어 연결을 모두 처리합니다.

2. **로컬 앱 시작**

   클라이언트 머신에서 HTTP 서비스를 실행합니다. 아래 예시는 Python 내장 서버를 사용합니다.

   ```bash
   python3 -m http.server 3000 --bind 127.0.0.1
   ```

3. **루트 도메인 터널 연결**

   `--subdomain`을 생략하면 루트 도메인 경로로 등록됩니다.

   ```bash
   proxer http 3000 \
     --server ws://your-server.example.com:8080 \
     --token dev-token
   ```

4. **루트 경로 테스트**

   ```bash
   curl -H 'Host: your-server.example.com' http://your-server.example.com:8080/
   ```

5. **서브도메인 경로 사용**

   이름이 있는 경로가 필요하면 `--subdomain`을 지정합니다.

   ```bash
   proxer http 3000 \
     --server ws://your-server.example.com:8080 \
     --subdomain demo \
     --token dev-token
   ```

   ```bash
   curl -H 'Host: demo.your-server.example.com' http://your-server.example.com:8080/
   ```

</Steps>

<Aside type="tip">
  로컬에서 테스트할 때는 `Host` 헤더가 어떤 터널로 갈지 결정합니다. 운영 환경에서는 DNS나 reverse proxy가 Proxer 서버를 가리키게 하고 원래 Host 헤더를 보존하세요.
</Aside>
