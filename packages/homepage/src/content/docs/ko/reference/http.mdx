---
title: proxer http
description: 터널을 통해 로컬 HTTP 서비스를 노출합니다.
---

`proxer http <port>`는 클라이언트가 시작한 터널을 공개 Proxer 서버에 연결하고 요청을 로컬 HTTP 포트로 전달합니다.

---

## 사용법

```bash
proxer http 3000 --server wss://your-server.example.com --subdomain demo --token dev-token
```

---

## 옵션

- `<port>` — 전달할 로컬 HTTP 포트입니다. 이 positional 인자에는 환경변수가 없습니다.
- `--server <url>` — 공개 Proxer 서버 URL입니다. Proxer는 내부적으로 항상 `/__proxer__/control`에 연결합니다.
- `--subdomain <name>` — 서브도메인 경로를 등록합니다. 생략하면 루트 도메인 경로를 등록합니다.
- `--token <token>` — 서버와 일치해야 하는 공유 토큰입니다.

토큰을 사용하는 공개 서버에는 `wss://`를 사용하세요. TLS는 Caddy, Traefik, NGINX 또는 로드 밸런서에서 종료하고 Proxer로는 loopback 또는 private network를 통해 전달할 수 있습니다.

`dev-token`은 데모/로컬 테스트용입니다. 실제 배포에서는 긴 난수 토큰을 `PROXER_TOKEN`, Docker/Kubernetes secret, 또는 플랫폼의 secret 메커니즘으로 전달하세요. CLI 인자는 shell history나 process list에 노출될 수 있습니다.

---

## 환경변수

- `PROXER_SERVER` — `--server` 기본값
- `PROXER_SUBDOMAIN` — `--subdomain` 기본값
- `PROXER_TOKEN` — `--token` 기본값

CLI flag가 환경변수보다 우선합니다.

---

## 루트 경로

`--subdomain`을 생략합니다.

```bash
proxer http 3000 --server wss://proxy.example.com --token dev-token
```

`proxy.example.com` 요청은 로컬 서비스로 전달됩니다.

---

## 서브도메인 경로

`--subdomain`을 지정합니다.

```bash
proxer http 3000 --server wss://proxy.example.com --subdomain demo --token dev-token
```

`demo.proxy.example.com` 요청은 로컬 서비스로 전달됩니다.

---

## 재연결 동작

이미 연결된 제어 연결이 끊기면 클라이언트는 재시도하고 서버가 다시 접근 가능해지면 재등록합니다. 초기 연결이 등록 전에 실패하면 명령이 종료될 수 있습니다.
