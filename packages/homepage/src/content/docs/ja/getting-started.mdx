## 前提条件

- HTTP/WebSocketトラフィックを受けられる公開マシン
- 公開したいローカルHTTPサービス
- npmでインストールする場合はNode.js 24以降

---

## インストール

<Tabs>
  <TabItem label="Windows">

    [GitHub Releases](https://github.com/tinyrack-net/proxer/releases)からWindows用の単体実行ファイルをダウンロードします。

    ```powershell
    proxer.exe --version
    ```

  </TabItem>
  <TabItem label="macOS / Linux">

    ```bash
    brew install tinyrack-net/tap/proxer
    ```

  </TabItem>
  <TabItem label="npm">

    npmはすべてのプラットフォームで使えるクロスプラットフォームなインストール方法です。

    ```bash
    npm install -g @tinyrack/proxer
    ```

  </TabItem>
  <TabItem label="Docker">

    ```bash
    docker run --rm tinyrack/proxer --version
    ```

  </TabItem>
</Tabs>

## 新しく始める

初めてProxerを使う場合は、次の手順で公開サーバーを1つ起動し、ローカルサービスを1つ公開します。

以下の公開`wss://`および`https://`の例は、Proxerの前段にあるreverse proxyまたはload balancerでTLSを終端し、loopbackまたはprivate network経由でProxerへ転送することを前提にしています。

<Steps>

1. **公開サーバーを起動する**

   公開トラフィックを受けるマシンでProxerを実行します。

   ```bash
   proxer server --listen 0.0.0.0:8080 --domain your-server.example.com --token dev-token
   ```

   このサーバーは同じポートで公開リクエストとトンネル制御接続を処理します。

2. **ローカルアプリを起動する**

   クライアントマシンでHTTPサービスを起動します。次の例ではPythonの組み込みサーバーを使います。

   ```bash
   python3 -m http.server 3000 --bind 127.0.0.1
   ```

3. **ルートドメインのトンネルを接続する**

   `--subdomain`を省略すると、ルートドメインの経路として登録されます。

   ```bash
   proxer http 3000 \
     --server wss://your-server.example.com \
     --token dev-token
   ```

4. **ルート経路をテストする**

   ```bash
   curl https://your-server.example.com/
   ```

5. **サブドメイン経路を使う**

   名前付きの経路が必要な場合は`--subdomain`を指定します。

   ```bash
   proxer http 3000 \
     --server wss://your-server.example.com \
     --subdomain demo \
     --token dev-token
   ```

   ```bash
   curl https://demo.your-server.example.com/
   ```

</Steps>

<Aside type="tip">
  インターネットに公開するデプロイでは、トンネルクライアントに`wss://`を使ってください。TLSはCaddy、Traefik、NGINX、またはロードバランサーで終端し、Proxerへはloopbackまたはprivate network経由で転送できます。
</Aside>

<Aside type="caution">
  `dev-token`はデモ/ローカルテスト用です。実運用では長いランダムトークンを`PROXER_TOKEN`、Docker/Kubernetes secret、またはプラットフォームのsecret機構で渡してください。CLI引数はshell historyやprocess listに露出する可能性があります。
</Aside>

<Aside type="tip">
  ローカルでテストするときは、`Host`ヘッダーがどのトンネルへ送られるかを決めます。本番ではDNSまたはreverse proxyをProxerサーバーへ向け、元のHostヘッダーを保持してください。
</Aside>
